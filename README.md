# foreman-handoff

Claude CodeやCodexの作業を、完成条件と検証済み状態を保ったまま別の主任へ引き継ぐスキル。利用枠が少なくなったときや、ユーザーが担当交代を指定したときに使います。

## できること

- 前任が、現物と照合した引き継ぎ書を作る。
- 後任が、現在の変更と権限を確認して施工を続行する。
- 許可された難所だけを別の担当へ委託する。

残量の自動監視、別サービスの起動、認証、モデル切り替え、メッセージ配送は付属しません。使える連携手段がない環境では、ユーザーが引き継ぎ書を後任へ渡します。ネットワーク通信や認証情報を扱う実行スクリプトは含みません。

## 構成

```text
foreman-handoff/
├── SKILL.md
├── README.md
├── templates/
│   └── handoff.md
└── LICENSE
```

## 導入

まずインストールせず、使用するエージェントに次のように指示できます。

```text
/path/to/foreman-handoff/SKILL.mdを読み、その手順で引き継ぎを準備してください。
```

常用する場合は、フォルダ全体を利用ツールが対応するスキル配置先へコピーします。一般的なユーザー単位の配置例は、Claude Codeでは `~/.claude/skills/foreman-handoff/`、Codexでは `~/.agents/skills/foreman-handoff/` です。既存フォルダがあれば上書きせず差分を確認してください。認識方法は利用中のバージョンに従います。

配置方法の公式資料：[Claude Code Skills](https://code.claude.com/docs/en/skills)、[Codex Skills](https://learn.chatgpt.com/docs/build-skills)。

## 使い方

### 前任へ

```text
foreman-handoffを使って引き継ぎを準備してください。
後任はLuna 6 Max、必要な難所担当はAstra xHighを希望します。
今回は準備まで。現在の完成条件と承認範囲を維持し、
引き継ぎ書の場所と、前任の書き込み停止状態を報告してください。
```

### 後任へ

```text
foreman-handoffを使い、指定した引き継ぎ書を受け入れて続行してください。
引き継ぎ書：/path/to/project/handoff.md
前任は対象への新しい書き込みを停止済みです。
通常作業は直接完遂し、具体的に必要な難所だけAstra xHighへ委託して構いません。
再委託は許可しません。既存の完成条件・操作の承認範囲を維持してください。
```

Opus 5.5 → Luna 6 Max、難所担当Astra xHighは設定例です。モデルの提供状況、識別子、effortは実行環境で確認してください。この文を貼るだけで実行中のモデルが切り替わることはありません。

## 引き継ぎ状態

| 状態 | 意味 |
| --- | --- |
| PREPARED | 前任が引き継ぎ書を準備した。後任の起動や受け入れは未確認。 |
| ACCEPTED | 後任が現在の状態と担当範囲を確認し、施工を引き受けた。 |

利用枠が回復しても自動で元の主任へ戻しません。引き継ぎによってcommit・push・本番操作などの権限も増えません。

## 検証範囲

配布ファイルの構造と参照を検証対象とします。実際のClaude CodeとCodex間の起動・配送・施工継続は、このパッケージだけでは保証しません。実運用では、最初の引き継ぎでPREPAREDとACCEPTEDが区別され、未commitの変更と権限が保持されることを確認してください。
