# 開始文の雛形

`<>` の部分を置き換えて、エージェントの入力欄に貼る。
開始文を貼っても、実行中のモデルは切り替わらない。相手の起動・送信は利用可能な手段とOwnerの承認範囲に従う。既存の専任会話を指定しているときは、新しい会話に黙って置き換えない。

## 開発役へ：開発を始める

```text
b2b-dev の開発役として作業してください。
目的：<目的と完成条件>
作業は branch <branch> で行い、検証の区切りごとに HANDOFF.md を更新してください。
監査役は <エージェント／モデル> です。合格位置より後の変更は、私の明示の指示がない限り、merge・push・deploy しないでください。
```

## 監査役へ：監査を始める

```text
b2b-dev の監査役として作業してください。
HANDOFF.md と AUDIT.md を読み、AUDIT.md の読了位置から HEAD まで（初回は <基点> から。未 commit の差分も含む）を監査し、読了位置と合格位置を分けて記録してください。
コードへの書き込みはしないでください。git には --no-optional-locks を付けてください。
書き込んでよいのは AUDIT.md だけです。
```

## 開発役へ：バトンタッチの準備（計画された交代）

```text
b2b-dev のバトンタッチを準備してください。
進行中の変更を検証済みの区切りまで進め、新しい変更は始めないでください。
HANDOFF.md の全節を更新し、状態を BATON-READY にしてください。
保存したらコードへの書き込みを止め、新しい開発役への開始文を示してください。
```

## 監査役へ：バトンタッチで開発を引き継ぐ

```text
b2b-dev のバトンタッチで、開発席を引き継いでください。
前の開発役 <エージェント> は HANDOFF.md を BATON-READY にして、書き込みを止めています。
まず途中の監査を AUDIT.md に書き出し、読了位置から HEAD まで（未 commit の差分も含む）の監査を終えてください。
それから HANDOFF.md と作業場所を照らし合わせ、HANDOFF.md を ACCEPTED（バトンタッチ）にして続けてください。
```

## 開発役へ：リリーフの準備（枠・コンテキストが危ない）

```text
b2b-dev のリリーフを準備してください。
区切りを待たずに、HANDOFF.md の冒頭の「状態」だけを今すぐ保存し、状態を SWAP-PREPARED にしてください。
保存したらコードへの書き込みを止め、新しい検証は走らせず、新しい開発役への開始文を示してください。
```

## 監査役へ：リリーフで開発を引き継ぐ

```text
b2b-dev のリリーフで、開発席を引き継いでください。
前の開発役 <エージェント> は <SWAP-PREPARED を保存して止まりました／保存できずに止まりました>。
前任の停止は <確かめた方法と時刻／まだ確かめていません>。
まず途中の監査を AUDIT.md に書き出し、まだ監査していない変更を監査してください。
「未照合」の項目と作業場所を照らし合わせ、前任の停止の根拠と、途中で止まった処理の安全を確かめてください。
停止の根拠が得られない、または安全を確かめられない処理があれば、受け入れずに私に報告してください。
すべて確かめられたら、HANDOFF.md を ACCEPTED（リリーフ）にして続けてください。
```

## 元の開発役へ：監査席に着く

```text
b2b-dev の監査役として戻ってください。今の開発役は <エージェント> です。
AUDIT.md の読了位置から HEAD まで（未 commit の差分も含む）を監査してください。コードへの書き込みはしないでください。
```

## 単発の修復を監査担当へ委任する

```text
今回だけ <課題> の開発を <担当・既存会話> へ委任します。継続的な役割変更ではありません。
基点：<正本・HEAD・dirtyの識別値>。編集してよい範囲：<写し／ファイル>。
元の開発者は対象への書き込みを止めています。完成条件：<条件>。
差分・対象一覧・SHA・試験結果・未確認を返し、返却後は書き込みを止めてください。
差分を書いていない <受入担当> が独立に受け入れます。適用・commit・DB等は <許可範囲> のみ。
返却後の担当配置：<開発者／主任監査者>。
```

## 追加監査を既存会話へ依頼する

```text
<担当・モデル> の <既存会話名・ID/URL・環境> で追加監査をお願いします。
主任監査者は <担当> です。対象：<基点・patch版とSHA・対象一覧>。
重点：<観点>。資料：<共有可能な出典>。読むだけ、書込は <指定監査書のみ／なし>。
自分で検証したこと、提出ログで確認したこと、未確認を分けて報告してください。
今回の許可は追加監査だけで、開発・適用・本番操作は含みません。
```

## 承認済み台本の実行代行

```text
Owner指示として <台本パス・識別値> の実行を承認します。対象：<写し／専用stack>。
<回数> 回だけ実行し、失敗時は <停止条件>。修正・再実行・installは <許可／禁止>。
STEP・終了コード・所要時間・試験集計・失敗した試験名を返してください。秘密は表示しないでください。
これは実行代行であり、開発席への交代や受入判定の依頼ではありません。
```

## 固定版の局所再判定

```text
<版> の再判定をお願いします。<依頼書>、<累積patchとSHA>、<前版からの増分とSHA>、<ログ> を確認してください。
対象の指摘：<ID>。書込は <AUDIT.md> の追記だけ。実適用・試験再実行・DB操作はしないでください。
指摘ごとのCLOSED／OPEN、新しい欠陥、読了位置と局所合格位置を記録してください。
Production <現在のOwner判定> を維持してください。
```
