# AUDIT（監査役が書く）

> 監査は読み取りだけで行う（git には `--no-optional-locks` を付ける）。
> 根拠には、ファイルと行、またはコマンドと出力を付ける。実際に測ったことと、推測を区別する。

## 監査の位置

- 監査役（エージェント・モデル）と日時：
- 主任／追加監査の別と、今回の差分の作者（自己監査と区別）：
- 読了位置（commit、または固定patch SHA・基点・対象一覧。合格は意味しない）：
- 合格位置（判定が「問題なし」で、高・中の指摘がすべて閉じている固定対象と局所範囲）：
- 監査した未 commit の変更の識別値（追跡外の新規ファイルを含む。例：`{ git --no-optional-locks diff HEAD --binary; git --no-optional-locks ls-files --others --exclude-standard -z | xargs -0 shasum; } | shasum`）：
- 今回監査した範囲：
- 判定：問題なし／直してから次へ／要ユーザー判断
